## NIM deployment → `cosmos3-inference-nim` (the cookbook's nested skill moves up; the pages stay)

The NIM row of the Inference Cookbook migration has no notebooks: upstream replaced `run_with_nim.ipynb` with the Cosmos3 NIM
cookbook pages and example clients (#296; see the `run_with_nim.ipynb` row above). The cookbook ships its own agent skill in a
hidden folder inside the cookbook directory, which agents started at the repository root do not discover (the repository's
skill roots are `.agents/skills/` and `.claude/skills/`). This row promotes that skill to
`.agents/skills/cosmos3-inference-nim/` (with the `.claude/skills/cosmos3-inference-nim` symlink) and retires the nested copy
(`.agents/skills/cookbooks/cosmos3/nim/.agents/skills/cosmos3-nim-user/SKILL.md`), so one copy exists; the cookbook's
`AGENTS.md`, `cosmos3-generate-media` (three links) and `tools/docs/site/agent_skills.md` point at the promoted skill. The NIM
pages, `AGENTS.md`, `examples/`, the pinned client environment (`pyproject.toml`, `uv.lock`) stay in
`.agents/skills/cookbooks/cosmos3/nim/` and remain the source of truth; the docs navigation keeps its "Deploy with NIM" entry
on the cookbook README. Moving the pages and the example clients into the skill directory is a later housekeeping change
(the clients find the shared assets through their position in the cookbook tree). `SKILL.md` quotes the
README's "Use an Existing NIM Endpoint" and deployment.md's bash blocks (verbatim, in page order) and keeps its longer skill
notes in `references/skill-notes.md` (skill-authored, nothing from a source). Sources: `main` at `bbd4a67`.
