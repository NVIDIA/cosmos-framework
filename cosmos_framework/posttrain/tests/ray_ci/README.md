# Ray CI suites

These suites provide bounded validation of the post-training Ray runtime without model checkpoints.

| Gate        | Coverage                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| CPU L0      | Actor startup and control-plane contracts, CPU placement and grid behavior, exact cursor handoff, GRPO reward-report barriers plus replica-local scored-handle routing and downstream bulk materialization, model-free two-rank Gloo online-NFT routing across source → rollout → reward → replay → policy with distributed group-relative aggregation and source/model clock convergence, rank-consistent diffusion/LLM non-finite rejection and recovery on Ray/Gloo grids, and imports of the user-facing examples. |
| CPU L1      | Four-actor Ray/Gloo mesh creation and `ParallelDims` injection.                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| Distributed | One physical CI node, two Ray actors, one GPU per actor, a real NCCL rendezvous, and rank-consistent diffusion/LLM non-finite rejection and recovery.                                                                                                                                                                                                                                                                                                                                                                  |

Distributed tests can request the `ray_two_gpu_hosts` fixture to receive isolated, automatically cleaned-up actors. They run only when the dedicated job sets `COSMOS3_POSTTRAIN_DISTRIBUTED_RAY_CI=1`, which prevents the generic L0 sweep from starting Ray or NCCL if its image later gains Ray. The dedicated job also requires Ray and two visible GPUs before pytest starts, so it cannot pass by skipping for missing dependencies or hardware.

Some legacy files mix CPU, single-node GPU, and multinode cases, so the CPU job selects their CPU tests in place instead of moving whole files under `cpu/`. The current gate deliberately excludes GRPO tests that download Hugging Face assets, HF model-building tests that require training-only dependencies, four-GPU and multinode placement, and full FSDP training and checkpoint flows. The distributed smoke subsumes the older model-free Ray rendezvous probe; the heavier cases remain in the GPU or on-cluster validation plan.

The online-NFT CPU smoke declares the production five-role ActorGroup with the scoped
`nft` exact-rank dispatch profile. It proves topology-free source → rollout → reward
→ replay → policy routing, distributed scalar aggregation, and converged structural
clocks only. It does not prove GPU capacity, FSDP gradient synchronization, live
reward-service transport, or model numerics.

Add future Ray correctness tests to the appropriate directory. GitLab discovers the whole directory, so adding a test does not require editing CI YAML. Runtime changes in the distributed, checkpoint, data, model, role, and entrypoint surfaces trigger the suites automatically. Changes to post-training examples also trigger the CPU import smoke; documentation, experiment recipes, and algorithm/reward-only changes do not. Keep cross-node networking, full-model execution, and long-running training validation in the on-cluster test plan.

The separate required CPU correctness gate covers the fast algorithm, parity, cursor, entrypoint, and trainer contracts, including algorithm/reward-only changes. Its reviewed node-ID manifest must execute exactly once with no skip or xfail. It complements these Ray suites: process isolation, cross-worker routing, Gloo/NCCL consensus, and GPU topology remain owned here rather than being duplicated in the CPU inventory.
